Executive Summary

This PRD specifies NeoStrike Reference Frontend v2.0 — a Slott-inspired casino portal replacing the current minimal Starter Kit frontend with a complete, player-ready iGaming experience. The v2.0 frontend is an MIT-licensed React application operators clone, brand, and deploy. No bespoke frontend build is required.

The design benchmark is Slott.com — specifically its lobby navigation architecture and individual game page layout. NeoStrike v2.0 retains all existing SDK hooks and adds the UI layers that currently require 3–5 weeks of operator effort. With v2.0, operator frontend work reduces to 2–4 days of branding and theming.

Scope Boundary
Frontend Reference implementation only. No new backend APIs, no new Fast Track events, no F8–F11 module changes. All data is sourced from existing SDK hooks. Gamification (XP, achievements, loyalty tiers) remain Fast Track Rewards' domain — NeoStrike renders Fast Track-provided data only.

Component C-03  ·  Game Page
Full game experience: top bar, tournament banner, iframe, RG session bar, right sidebar

Overview
The game page is the most significant addition in v2.0. Based on the Slott game page layout, it delivers a two-column design: a game frame area with persistent controls and contextual overlays, plus a right sidebar. The left navigation panel present in some Slott layouts is explicitly excluded per product decision.

Layout Decision — No Left Panel
Two-column layout only: game frame area (flex: 1) + right sidebar (fixed 290px). This maximises iframe size on desktop and simplifies mobile collapse to full-width iframe with sidebar accessible as a bottom sheet.

	•	iframe src — set by useGameLaunch(gameId, { mode }). Provider-specific URL from Game Provider Adapter. For NeoStrike Demo Slot, serves the built-in HTML5 game (C-07).

C-03d — RG Session Bar
Persistent slim bar below the iframe on every game page. Never dismissible.

	•	Progress bar: current session duration vs. player's session time limit from useRGLimits()
	•	Colour progression: green → amber at 75% → red at 90%
	•	'Edit limits' shortcut: opens Account Dashboard to RG tab without interrupting the game session
	•	No limit set: shows 'No session limit set' with 'Set limit' CTA
	•	F11 Prolonged Session trigger: bar pulses red, modal prompts break. Wired to existing F11 in-session detection.

Regulatory Rationale
UKGC Social Responsibility Code requires players to access limit-setting tools without disrupting their session. The RG session bar satisfies this requirement on every game page — including the demo slot — ensuring the compliance story is demonstrable in every sales demo.

C-03e — Right Sidebar: Game Info Tab
Game Info Panel
Structured metadata for the current game: RTP %, volatility, max win multiplier, bet range, mechanic tags as styled chips. For NeoStrike Demo Slot: RTP 96.00%, High volatility, 500x max win, €0.20–€5.00 bet range, DEMO and SEAMLESS WALLET tags.

Rank Card
Player's current rank and XP progress bar. Data from Fast Track Rewards player profile (read-only). Hidden if Fast Track rank data unavailable. NeoStrike implements no fallback rank engine.

Recent Sessions
Last 5 game sessions: thumbnail, name, provider, date, net result. For the NeoStrike Demo Slot, a live 'Now — active' row appears at the top of the list while a session is in progress, updating the net P&L in real time. Sourced from usePayments().getHistory() for real provider games; from the Seamless Wallet Bridge (C-09) for the demo slot.

C-03f — Right Sidebar: Related Games Tab
Surfaces similar games to keep players in session. Powered by useRelatedGames(gameId) (C-06). NeoStrike Demo Slot is related to all Pragmatic Play and NetEnt slots by provider and volatility matching — ensuring related games always contains real provider options to demonstrate the full catalog.

Acceptance Criteria — Game Page
	•	Game page route loads and iframe initialises within 3 seconds on 10Mbps connection.
	•	Session clock starts on first WAGER event — not on page load. Demo slot WAGER events count.
	•	Demo toggle sends MODE_CHANGE message to iframe via C-09 Seamless Wallet Bridge. Wallet balance unchanged in demo mode.
	•	RG session bar updates every 60 seconds. At 90% of session limit, non-blocking toast prompts player.
	•	useRelatedGames() results render within 200ms of page load (served from cached Game Catalog data).
	•	Right sidebar hidden on mobile (< 768px). Accessible via bottom sheet triggered by 'Dashboard' button in top bar.
	•	Live session row in Game Info tab updates net P&L within 500ms of each spin result during demo slot play.

Component C-05  ·  useGameLaunch() Hook
Game launch URL resolution with demo / real money mode

Overview
Standardises game launch URL resolution across all providers and the NeoStrike Demo Slot. For real provider games, returns the authenticated Seamless Wallet URL. For the demo slot (gameId: 'neostrike-demo'), returns the built-in HTML5 game document directly without an external URL fetch.

useGameLaunch() — Signature
const { launchUrl, isLoading, error } = useGameLaunch(gameId, options?)

Options: { mode: 'real' | 'demo', currency?: string, locale?: string }

Behaviour
	•	mode: 'real' — authenticated Seamless Wallet launch URL for real provider games; for demo slot, enables wallet debit/credit via C-09 bridge
	•	mode: 'demo' — provider demo URL for real provider games; for demo slot, disables wallet integration (free play, no balance change)
	•	gameId: 'neostrike-demo' — returns built-in HTML5 game srcdoc; no external URL fetch; no provider contract required
	•	Provider without demo support: error returns DEMO_NOT_SUPPORTED; demo toggle disabled with tooltip
	•	Launch URLs cached for session duration — repeated calls for same gameId+mode do not re-fetch

Acceptance Criteria
	•	Returns valid launch content within 200ms for all games including demo slot.
	•	Demo mode URL contains no player JWT or session token.
	•	gameId 'neostrike-demo' resolves without any network request.
	•	DEMO_NOT_SUPPORTED renders as disabled toggle with tooltip — not a runtime error.

Component C-07  ·  NeoStrike Demo Slot
Proprietary HTML5 slot game for sales demos and operator onboarding

Purpose and Scope
NeoStrike Demo Slot is a proprietary, self-contained HTML5 slot game built to serve two specific use cases: sales demonstrations to prospects who do not yet have a provider contract, and operator onboarding testing where operators need to validate wallet, bonus, and RG flows before their provider integration is live.

Scope Constraint
The demo slot is not a commercial game. It is not subject to RNG certification, gaming licence requirements, or player accessibility by the general public. It is a demonstration and testing tool only. It must never be presented to players as a real gambling product. The demo/real money toggle must always be visible and clearly labelled when the demo slot is loaded.

Game Mechanic
A 3-reel, 1-payline slot with 6 symbol types. All game logic runs client-side in the browser. The RNG uses Math.random() — not a cryptographically certified RNG. This is intentional: the demo slot demonstrates the platform integration, not the statistical properties of the game.

Component C-08  ·  Fast Track Event Feed
Live WAGER/WIN event visualiser for demo and onboarding contexts

Overview
The Fast Track Event Feed is a non-intrusive overlay panel that appears in the bottom-right corner of the screen whenever the NeoStrike Demo Slot is active. It visualises the WAGER and WIN events that NeoStrike would publish to Fast Track Rewards in a live operator environment — making the event flow tangible and demonstrable to sales prospects and operators in onboarding.

Display Context
The Fast Track Event Feed is shown only when the demo slot game page is active. It is hidden on the lobby page and on real provider game pages. Its purpose is purely demonstrative — in a production operator environment, Fast Track events are consumed server-side by Fast Track Rewards and are not visible to players.

Feed Behaviour
	•	Positioned: fixed bottom-right, 16px from edges, z-index above game page but below wallet modal
	•	Shows last 5 events maximum — older events scroll out automatically
	•	Each event entry: event name (bold, primary colour), detail string, amount (positive green / negative muted)
	•	New events slide in from the right with a 300ms CSS animation
	•	Events displayed: WAGER, WIN, LOGIN (session start), MODE_CHANGE (demo/real switch)
	•	WIN events include symbol combination and multiplier in the detail string

Component C-09  ·  Seamless Wallet Bridge
postMessage protocol connecting demo slot iframe to parent wallet state

Overview
The Seamless Wallet Bridge is the integration layer that allows the NeoStrike Demo Slot — running inside a sandboxed iframe — to communicate balance changes and game events to the parent page. It mirrors the role of the Seamless Wallet API (F9) in a real provider integration: the parent page acts as the wallet server, the iframe acts as the game client.

Why postMessage?
Real provider games communicate with NeoStrike's Seamless Wallet via server-to-server API calls (provider server → NeoStrike wallet endpoint). The demo slot runs entirely in the browser with no server component. The postMessage API is the browser-native equivalent — it allows the iframe (game) to send structured messages to the parent window (wallet) with the same security boundary as a cross-origin server call.

Message Type
Payload
Parent Action
BALANCE_UPDATE
{ type, real: number, win?: number }
Updates useBalance() state; refreshes wallet modal display; updates live session row in sidebar

{ type, event: string, detail: string, amount: number|null }

Message Protocol — Parent to Iframe
Message Type
Payload
Iframe Action
MODE_CHANGE
{ type, demo: boolean }
Switches between demo and real money mode; updates mode indicator strip
BALANCE_SYNC
{ type, real: number }
Updates the balance display inside the game UI to match the current parent wallet state

Security Constraints
	•	All postMessage calls from the parent specify targetOrigin: '*' in development and the operator's domain in production — messages are never broadcast to arbitrary origins in production.
	•	The iframe is sandboxed with allow-scripts allow-same-origin — it cannot access localStorage, cookies, or other browser APIs outside the game sandbox.
	•	No financial data is persisted inside the iframe — all balance state lives in the parent page's useBalance() hook.
	•	BALANCE_UPDATE messages from the iframe are validated: the debit amount must match the current bet denomination, and the credit amount must match a valid payout multiple. Mismatched amounts are rejected silently.

Acceptance Criteria
	•	BALANCE_UPDATE message from iframe updates the parent wallet display within 200ms.
	•	MODE_CHANGE message from parent updates the iframe's mode indicator within 200ms.
	•	Wallet balance in parent and wallet balance displayed inside the demo slot are always identical within 1 second of any spin result.
	•	Switching mode from real to demo while a spin is in progress does not cause a balance inconsistency — in-flight spin resolves in the mode it started in.
	•	Navigating away from the game page (back to lobby) while a spin is in progress does not cause an orphaned balance debit — the parent validates all BALANCE_UPDATE messages against an active session flag.
